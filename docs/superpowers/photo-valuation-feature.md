# Спецификация: Автоматическая оценка рыночной стоимости по фотографиям

**Статус:** Черновик
**Область:** `src/app/(frontend)`, `src/payload`, `src/api`

---

## 1. Контекст

Текущий процесс оценки объектов недвижимости (квартир, домов, коммерческой недвижимости) часто требует выезда специалиста или длительного ручного анализа предоставленных фотографий. С развитием AI-моделей компьютерного зрения (Vision) появилась возможность автоматически анализировать фотографии интерьера и экстерьера для определения состояния ремонта, качества отделки, наличия техники и мебели, что напрямую влияет на рыночную стоимость объекта.

## 2. Цели

- Предоставить пользователям (и агентам) инструмент для быстрой предварительной оценки стоимости недвижимости на основе загруженных фотографий.
- Интегрировать процесс загрузки и анализа фотографий в существующий флоу подачи заявки или добавления объекта.
- Использовать LLM с поддержкой Vision (например, GPT-4o, Claude 3.5 Sonnet или аналоги) для анализа изображений и извлечения признаков (состояние ремонта, класс жилья, наличие дефектов).
- Сформировать прозрачный отчет об оценке, объясняющий, какие факторы на фотографиях повлияли на итоговую стоимость (повышающие или понижающие коэффициенты).

## 3. Не-цели

- Полная замена профессиональной оценки недвижимости (инструмент носит рекомендательный характер).
- Анализ юридической чистоты объекта.
- Точная оценка стоимости без учета макроэкономических факторов, района и инфраструктуры (фотографии — лишь один из параметров).
- Обучение собственной нейросети с нуля (используем готовые API).

## 4. Пользовательский сценарий (User Flow)

1. **Загрузка данных:** Пользователь заходит на страницу оценки, вводит базовые данные (адрес, площадь, этаж) и загружает от 3 до 10 фотографий объекта (кухня, санузел, комнаты, вид из окна).
2. **Препроцессинг:** Frontend отправляет фотографии на сервер (Next.js API route), где они при необходимости сжимаются.
3. **Анализ AI:** Сервер отправляет фотографии через API в Vision-модель с промптом:
   - "Оцени состояние ремонта (без ремонта, косметический, евроремонт, дизайнерский)."
   - "Определи наличие и качество мебели/техники."
   - "Выяви видимые дефекты (плесень, разбитые окна, голые стены)."
4. **Расчет стоимости:** Полученные от AI признаки объединяются с базовыми характеристиками (локация, площадь). Применяется эвристическая модель или регрессия (опирающаяся на исторические данные продаж из Payload CMS/PostgreSQL), корректирующая базовую цену.
5. **Вывод результата:** Пользователь видит примерную вилку стоимости объекта и карточки с выделенными AI преимуществами (например, "Новый ремонт в ванной: +5% к стоимости") и недостатками ("Требуется замена полов: -3% к стоимости").

## 5. Техническая реализация

### Frontend (Next.js 15, React 19)
- Компонент Drag-and-Drop для загрузки множества изображений.
- Индикация процесса (скелетоны, прогресс-бары) во время работы AI-модели, так как запрос может занимать 10-30 секунд.
- Использование Server Actions или API Routes для безопасного взаимодействия с внешними API.

### Backend (Payload CMS & Drizzle ORM)
- Сохранение сессий оценки в базу данных (в новую коллекцию `Valuations` в Payload CMS) для последующей аналитики и дообучения ценовых моделей.
- Реализация пайплайна, который:
  1. Принимает изображения.
  2. Вызывает внешнее API (например, OpenAI API `gpt-4o`).
  3. Парсит структурированный JSON-ответ от AI.
  4. Применяет бизнес-логику расчета стоимости, используя данные о локации (учитывая геокодинг в хуках Payload).

### Интеграция AI
- **Промпт-инжиниринг:** Разработка надежного системного промпта, который возвращает ответ в строгом JSON-формате (используя Function Calling/Structured Outputs).
- Учитываем текущий пайплайн Yandex Speller для текстовых данных (возможно, интеграция с другими инструментами для текстовых описаний объекта).

## 6. Риски и ограничения

- **Галлюцинации AI:** Модель может ошибочно принять текстуру обоев за плесень или не заметить очевидных дефектов из-за плохого освещения на фото.
- **Время ответа:** Загрузка и анализ нескольких изображений высокого разрешения может занять значительное время. Необходима асинхронная обработка или оптимизация изображений перед отправкой (сжатие на клиенте).
- **Приватность:** Необходимо убедиться, что пользователи не загружают фото с чувствительной информацией (документы, лица), возможно, потребуется предварительная фильтрация.
